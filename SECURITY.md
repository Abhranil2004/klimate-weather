# Security Policy

## Supported Versions

We actively support the following versions of the project. If you're using an older version, we recommend upgrading to the latest release for security patches.

| Version        | Supported          |
| -------------- | ------------------ |
| 1.x (latest)   | ✅ Fully supported |
| < 1.0          | ❌ No longer supported |

---

## Reporting a Vulnerability

We take the security of our project seriously. If you find a security vulnerability, please follow these steps:

1. **Do not disclose publicly.**  
   Avoid sharing details of the vulnerability in public forums like GitHub issues or discussion boards.

2. **Contact us privately.**  
   Send a detailed report of the vulnerability to our security team:
   - **Email**: [abhranildutta1903@gmail.com](abhranildutta1903@gmail.com)

3. **Information to Include:**  
   - A description of the vulnerability.
   - Steps to reproduce the issue.
   - Potential impact.
   - If possible, a suggested fix.

4. **Response Time:**  
   - We aim to acknowledge receipt of your report within **48 hours**.
   - A detailed response, including next steps, will follow within **5 business days**.

5. **Resolution:**  
   Once the vulnerability has been addressed, we will work with you to disclose it responsibly and credit you for your efforts (if desired).

---

## Scope of Vulnerabilities

We are particularly interested in vulnerabilities related to:
- Unauthorized access to user data.
- Security flaws in authentication or authorization mechanisms.
- Potential data breaches or leaks.
- Code injection or cross-site scripting (XSS).
- Server-side vulnerabilities.
